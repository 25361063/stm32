# STM32F103C8 学习项目集

蓝色板（STM32F103C8）上的寄存器级裸机练习项目，不依赖 HAL/标准外设库，直接用寄存器操作。
工具链：Keil MDK-ARM（Arm Compiler 6.24）命令行编译，OpenOCD + ST-Link 烧录。

## 目录

| 目录 | 内容 |
|---|---|
| `点亮led/` | PA5 上外接 LED 闪烁 |
| `蜂鸣器/` | 双声部（TIM3_CH1 + TIM2_CH1）无源蜂鸣器演奏《卡农》8 段变奏 |
| `OLED调试/` | SSD1306 OLED 显示 DHT11 温湿度 + 温度折线图 |
| `蓝牙调试/` | BLE 蓝牙串口模块收发（心跳/回显）+ 中文 OLED 状态界面 |
| `超声波调试/` | HC-SR04 超声波测距 + 蓝牙距离状态报文 + 中文 OLED 界面 |

## 烧录器接线（ST-Link → 开发板）

| ST-Link | 开发板 |
|---|---|
| SWDIO | SWDIO |
| SWCLK | SWCLK |
| GND | GND |
| 3.3V | 3.3V |

BOOT0 跳线帽保持接 GND（从 Flash 启动），无需改动。

## 点亮led

| 器件 | 接到 |
|---|---|
| LED 长脚（正极，+） | 经 220Ω ~ 1kΩ 限流电阻到 **PA5** |
| LED 短脚（负极，-） | GND |

PA5 配置为推挽输出，输出高电平点亮、低电平熄灭。

## 蜂鸣器（双声部卡农）

两路蜂鸣器使用完全相同的驱动电路，各用一颗 S8050 三极管做低边开关：

| 器件 | 接到 |
|---|---|
| **PA6**（旋律声部，TIM3_CH1） | 1kΩ 电阻 → S8050 基极（B） |
| **PA0**（低音声部，TIM2_CH1） | 1kΩ 电阻 → 第二颗 S8050 基极（B） |
| S8050 发射极（E） | GND |
| S8050 集电极（C） | 无源蜂鸣器负极（-） |
| 无源蜂鸣器正极（+） | 3.3V |

注意事项：

- S8050 的 E / C 脚接反会导致蜂鸣器不响或声音明显变小，注意封装上的丝印方向。
- 使用**无源**蜂鸣器，靠 2 ~ 4kHz 方波发声（代码里已用 PWM 产生）；有源蜂鸣器接上只会听到固定音调。
- 基极必须串 1kΩ 电阻，不要直接接到 IO。

## OLED调试（OLED + DHT11 温湿度 + 折线图）

### 接线

| 器件 | 引脚 | 接到开发板 |
|---|---|---|
| OLED（四线 I2C） | GND | GND |
| OLED | VCC | 3.3V |
| OLED | SCL | **PB6** |
| OLED | SDA | **PB7** |
| DHT11 | VCC（第 1 脚） | 3.3V |
| DHT11 | DATA（第 2 脚） | **PA1**，同时经 10kΩ 电阻上拉到 3.3V |
| DHT11 | NC（第 3 脚） | 悬空，不接 |
| DHT11 | GND（第 4 脚） | GND |

DHT11 方向识别：**网格面（能看到小孔阵列的一面）朝向自己、引脚朝下，从左到右依次是 VCC、DATA、NC、GND**。接反可能损坏传感器，接线前先核对。

其他要点：

- OLED 模块自带 4.7kΩ I2C 上拉电阻，无需外接；DHT11 是裸传感器，DATA 线必须外接 10kΩ（4.7k ~ 10k 均可）上拉到 3.3V。
- 屏幕用 3.3V 供电，与 MCU 逻辑电平一致。

### 屏幕显示内容

```
T=30C H=77%          当前温度 / 湿度
OK  6 ERR  0 L0      读取成功次数 / 失败次数 / 最近一次错误码（L0=成功，L1~L6=各类超时或校验错误）
[ 温度折线图 ]        128 个采样点（每 2 秒一个，约 4 分钟窗口），量程自动缩放
```

### 实现说明

- OLED：PB6/PB7 上软件模拟 I2C（开漏输出），驱动 SSD1306 128x64；开机自动探测 0x3C / 0x3D 地址。
- DHT11：PA1 单总线，TIM4 提供 1µs 计时基准测量脉冲宽度；所有等待都有超时保护，传感器掉线不会卡死程序。
- 折线图：128 字节温度历史数组，新样本从右侧进入，纵轴按窗口内最小/最大值自动量程（最小跨度 4°C）。

## 蓝牙调试（BLE 蓝牙串口模块 + OLED 状态显示）

### 接线

| 蓝牙模块 | 接到开发板 | 说明 |
|---|---|---|
| VDD | 3.3V | |
| GND | GND | 必须共地 |
| TXD | **PA10**（USART1_RX） | ★ 交叉：模块发 → MCU 收 |
| RXD | **PA9**（USART1_TX） | ★ 交叉：模块收 → MCU 发 |
| LED | 悬空 | 状态指示输出脚，不接不影响通信 |

OLED 接线与上一节相同（GND/VCC/SCL→PB6/SDA→PB7）。

### 模块参数（实测）

- 广播名：**XLBLE**——是 BLE 低功耗蓝牙模块，**不支持经典蓝牙 SPP**（"蓝牙串口助手"类 App 搜不到它）
- 串口波特率：**115200** 8N1（出厂默认，固件已按此配置；8MHz 下 BRR = 0x45）
- 与手机的数据通过 GATT 特征值透传（见下）

### 手机端调试步骤（安卓）

1. 安装 BLE 调试 App（如"BLE调试助手"或 nRF Connect）
2. 连接 **XLBLE**
3. **打开"启用通知"开关（订阅）**——必须做，否则接收永远为 0
4. 特征值：发送用 `FFE1`，接收/通知用 `FFE2`（不同批次可能不同，挑带 Notify 属性的那个）
5. 连接后每 2 秒收到一行 `STM32 BT OK n`；发送 `hello` 会原样回显

### 屏幕显示（中文界面）

```
蓝牙 115200
接收 12 发送 30     收到字节数 / 已发心跳数
活动 *             近 2 秒内有数据到达
最近 hello          最近收到的 11 个可打印字符
```

### 串口调试经验（踩坑记录）

- **一根接收线上只能挂一个"发送方"**：MCU 的 PA10 同时接蓝牙模块 TXD 和 CH340 TXD 时，两个输出互相压制，双方都收不到数据，必须二选一（靠插拔切换）。
- **用 CH340 独立验证 MCU 串口**：CH340 的 RXD→PA9、TXD→PA10，发什么回什么说明固件和线路都正常；测蓝牙时把 CH340 数据线拔掉。
- **模块沉默时优先怀疑波特率**：让固件按顺序轮换几档波特率（每档 12 秒）并发送 `BAUD=xxxx` 标记，手机端哪一档能读出文本，哪一档就是模块真实波特率。
- **OLED 刷屏要先清屏再画**：可变内容（数字、指示符）不清屏会与旧像素叠加成糊块（"重叠"现象）。
- **中文字库**：`font_data.h` 由 `gen_font.ps1`（系统黑体渲染 16x16 点阵）生成，需要新汉字时改脚本里的编码列表重新生成即可。

## 超声波调试（HC-SR04 测距 + 蓝牙距离报文 + OLED 状态显示）

### 接线

| HC-SR04 | 接到开发板 | 说明 |
|---|---|---|
| VCC | 5V（板子无 5V 时接 3.3V） | 模块标称 5V 供电；3.3V 下量程/稳定性略降 |
| GND | GND | 必须共地 |
| TRIG | **PA2** | MCU 输出 12µs 高电平触发一次测距 |
| ECHO | **PA3** | 回波高电平，脉宽 µs ÷ 58 = 距离 cm（PA3 为 5V 容忍引脚，5V 回波可直接接） |

蓝牙模块（TXD→PA10 / RXD→PA9，交叉，详见上一节）和 OLED（SCL→PB6 / SDA→PB7）接线不变；PA1 上的 DHT11 保持不动、本工程不使用。

### 功能

- 每 200ms 测距一次，OLED 第一行显示实时距离，无效/超量程显示 `--- cm`
- 量程约 2 ~ 400cm；对着空气或超出 4m 读不到回波属正常
- 蓝牙：上电发 `STM32 US ready`；之后每 2 秒一行状态报文，内容随本工程功能（超声波）变化：

  ```
  STM32 US OK 3 D=123cm     3=计数，无回波时为 D=---
  ```

  收到什么仍原样回显（同蓝牙工程）
- 时序取舍：距上次收到串口数据 50ms 内不启动测量，串口空闲 300ms 且距上次刷屏 400ms 才刷新屏幕，避免测量/刷屏阻塞期间丢串口数据

### 屏幕显示

```
距离 123 cm          实时距离（无效/超量程时为 --- cm）
蓝牙 115200          串口参数
接收 12 发送 3       收到字节数 / 已发状态报文数
最近 hello           最近收到的 11 个可打印字符
```

### 踩坑记录

- **ECHO 上升沿延迟各模块差异大**：本模块从 TRIG 触发到 ECHO 拉高约 **2.2ms**（常见模块约 0.5ms）。等待窗口最初按常规设 2ms，出现"上电第一次能测、之后全部超时"的怪现象——每次都差 230µs 超时；放宽到 10ms 后 100% 正常。**等回波的超时窗口要按模块实测数据调整**。
- **用诊断固件定位硬件问题**：出现"触发后收不到回波"时，写了临时诊断固件把每次触发的上升沿等待时间、回波脉宽、TRIG 引脚回读电平存到内存数组，再用 OpenOCD `dump_image` 导出分析——56 次触发全部有回波（上升沿稳定 2.23ms），从而确认为软件超时窗口问题而非接线问题，避免了盲目怀疑硬件。
- 上电后第一次循环测量紧跟着初始化测量发出，模块来不及响应可能失败 1 次，之后全部正常，属正常现象。

## 编译方法（命令行）

各工程的 `Objects/` 目录下执行：

```powershell
# 编译（以 OLED调试 为例，armclang 位于 Keil 安装目录）
armclang --target=arm-arm-none-eabi -mcpu=cortex-m3 -O2 -c main.c -o Objects\main.o
armclang --target=arm-arm-none-eabi -mcpu=cortex-m3 -O2 -c startup.c -o Objects\startup.o
armlink --cpu=Cortex-M3 --scatter scatter.sct Objects\main.o Objects\startup.o -o Objects\oled.axf
fromelf --bin --output Objects\oled.bin Objects\oled.axf
```

烧录（OpenOCD）：

```powershell
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg -c "program Objects/oled.bin 0x08000000 verify reset exit"
```

> 说明：本机用户名含撇号（`'`），Keil uVision 图形界面编译会因路径解析报错，因此统一用命令行工具链编译。
> 各工程也有对应的 Keil 工程文件（`.uvprojx`），在无特殊字符路径的电脑上可直接用 uVision 打开。

## 备注

- `startup.c` 中包含 RW 数据拷贝（Flash → RAM）与 ZI 段清零，这是带初值全局变量能正常工作的前提。
- 每个工程均为独立目录，包含 `main.c`、`startup.c`、`scatter.sct` 和 Keil 工程文件。
